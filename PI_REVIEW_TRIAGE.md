# TensorFold review importance triage

Review baseline: `ddalcu/mlx-serve`, revision `3129a772b4a5a46678e44902b82db4bed42fa737`. This is an interim, evidence-ranked triage, not the final sweep report. The sweep is ongoing.

The review target's seven modified source files have been restored to the baseline without switching its branch. Eight earlier proposals are preserved in isolated branches/worktrees and PRs in the user's fork: five drafts and three closed, rejected archives. Nothing is merged. This triage adds documentation only; it does not change reviewed source or stop the running sweep.

## Priority and confidence

- **P1 — urgent:** release-blocking or immediately harmful behavior with demonstrated production reachability. No finding in this interim triage meets that evidentiary bar.
- **P2 — normal:** user-visible correctness, persistence, lifecycle, or meaningful test-integrity defects; schedule a focused fix after validating any remaining assumptions.
- **P3 — low:** narrower diagnostics, test specificity, tooling delays, or policy/maintenance improvements.
- **Rejected / excluded:** evidence contradicts the report, reachability is not established, or no actionable consequence is demonstrated. Do not turn these into fixes merely to satisfy the model report.

Confidence is independent of priority:

- **Reproduced:** actual project code was exercised; original results are recorded in [PI_REVIEW_NOTES.md](PI_REVIEW_NOTES.md), and migration smokes in the individual PR evidence documents. Browser and native migration smokes were actually run during this migration; older reproductions were not rerun for this document.
- **Source-supported:** inspected code establishes the stated mismatch/control flow, but the user-visible failure or proposed fix has not received a runtime smoke here.
- **Candidate:** a relevant source pattern exists, but a required reachability/lifecycle assumption remains unresolved.
- **Model-only / unchecked:** an observation in `.pi-sweep` has not been independently established. Original model severity is not an accepted severity.
- **Rejected:** existing verification or inspected control flow contradicts the claimed defect.

No verified high/critical security finding is established by the existing ledger or this triage.

## Corrections, rejected findings, and unchecked observations

- **Rejected:** batch **108:5**, append/pop aliasing. The existing actual-renderer alias reproduction produced `[1, 2]`, consistent with Python shared list mutation. Copying to “fix” it would break that behavior.
- **Rejected / excluded in the existing ledger:** batch **105** lexer OOB cases and null C-API reachability, **100/102** redundant/self-equal assertions, **101** source-text assertion observation, and **103** claimed continuation after a failing GNU Make recipe line. See the ledger for the distinguishing evidence; these are not actionable native fixes.
- **Partially contradicted by source:** batch **34:3** really uses substring weekday matching, but its example “every 30 minutes on my wedding anniversary” returns through interval parsing first (`ScheduleParser.swift:45–54`). The weekly-override example is rejected. Other false weekday matches remain a lower-priority candidate requiring realistic input/confirmation-path assessment.
- **Lower-priority source pattern, not urgent:** batch **27:2**, `Glob.matches` (`FileSearcher.swift:9–37`) escapes `.` but interpolates other regex-special literal characters. Literal filenames/globs can match incorrectly. Establish the intended glob syntax and a consumer-level counterexample before changing it.
- **Policy, not a demonstrated failure:** batch **2:2** observes `latest-stable` Xcode in release CI. Reproducible toolchain pinning may be worth discussing, but no release breakage was established. Its suggested Xcode 16 pin must not be adopted blindly: current package comments require the newer Swift/Xcode toolchain.
- **Remaining observations stay Model-only / unchecked:** subprocess pipe/timeout claims (**22:2**, **27:4**), HF model-ID path manipulation (**27:3**), sentence chunking (**34:2**), stalled speech-recognition callbacks (**40:2**), stale launcher temp files (**55:2**), test-recorder race (**71:2**), benchmark `eval` and sidecar evaluation/download claims (**128:3,5,6**), request timeout/temp-path/diagnostic claims (**140:2**, **155:2–4**), sound diagnostics/Linux cleanup/extra-argument splitting (**167:1,3,6**), and the remaining timeout/Python-quoting/temp-file/build-error claims in **169**. They are not independently reproduced by this triage; original report remedies and severities are not accepted automatically. In particular, quoting a multi-argument environment variable as one argument is not automatically a correct fix.

- The durable ledger records an initial enumeration of **1,072 source files in 172 batches**. Additional sweep output exists and the sweep remains ongoing; those initial figures are not a completed-coverage count.
- Generic sweep inline input is capped at **400,000 bytes per file**; oversized native files are truncated. This is not an all-lines review.
- This document preserves existing reproductions, inspects selected Swift/tooling/web source paths, and records actual native/browser migration smokes. It does not rerun the full review or confirm every model observation.
- Separate MLX/Metal checklists were read during the earlier review; targeted local-model/performance coverage remains incomplete. No performance or all-model correctness conclusion follows from these findings.
- Prior checks of the existing website logic and console/metrics suites passed, but are not evidence for stalled-network behavior. The migration adds the focused browser smokes described above. No full native server build, Swift app suite, model download, dependency installation, or inference benchmark is claimed.
