# Speculative lookup and verification-width selection

## Scope and attribution

The concepts of multi-source speculative drafting, suffix lookup and hardware-cost-aware StairCut selection are credited to [TandemLLM](https://github.com/0xBakeer/TandemLLM), by Khaled Bakeer. This feature belongs in **mlx-serve**: its host owns candidate preparation, verification, KV/SSM commit, request publication and speculative scheduling. mlx-stream's opaque DeepSeek `DraftLane` would require a separate interface change; its Engram table is not a continuation cache.

**Authoring provenance:** earlier local implementations were acknowledged source-derived ports. They have been removed, not renamed or retained as compatibility shims. The replacements in `token_history.zig`, `speculation_policy.zig` and `lookup_adapter.zig` were newly authored from behavioral/interoperability contracts and this project's performance observations. Initial replacement authors were excluded from the identified TandemLLM implementations and retired local port modules. The parent subsequently integrated and revised those components using host tests, new measurements and adversarial findings; the parent had previously seen the old implementation. Integration uses the existing host-native verifier and scheduler. This is not a clean-room certification or a claim that every contributor was source-unexposed.

Declared read sets and retired local artifacts are retained privately for audit. TandemLLM identifies its code as AGPL-3.0-only and documentation as CC BY 4.0; mlx-serve's own code is MIT, with separate dependency notices. Concept attribution is not a permission grant. Independent replacement and clean feature history are **not legal certification**, nor do they resolve obligations from historical distribution or third-party code.

The feature branch starts at upstream `191da71de32a65f69ebceeb6cb2e91036ab50b30`; intermediate local ports and experimental merge history are not part of the feature patch. This does not assert that prior work never existed. The existing fork can carry the upstream-based branch; no force-push or replacement fork is necessary.

## Architecture

| Component | Responsibility |
|---|---|
| `src/token_history.zig` | Bounded incremental request history; immutable corpus/persistent indexes; source-tagged proposals; validated storage and request-scoped leases |
| `src/speculation_policy.zig` | Calibrated proposal reach; ancestor-closed width selection; settled prices; paired remaining native duration/yield; bounded recovery probes |
| `src/lookup_adapter.zig` | Host candidate conversion, duplicate evidence merging, context classes and pre-assistant routing |
| `src/generate.zig` | MTP/PLD chain selection, supported DFlash tree integration, actual settled observations and publication-aware history |
| `src/transformer.zig` | Model-owned policies/index cache; native verification and opt-in dispatch instrumentation |
| `src/lookup_counterfactual.zig` | Diagnostic state/offer fingerprints, learner reset, exact first-offer publication and warmup qualification |

The three **history storage sources** are request-local prompt plus committed output, a static tokenizer-matched corpus, and completed cross-request history. These are not the three mechanisms “neural drafting / learned n-gram embeddings / suffix lookup.” Qwen PLE and DeepSeek Engram provide architecture-required embedding vectors, not proposed next-token IDs; disabling them changes the target model and is not a same-model speculation ablation. Matching in the suffix store respects document boundaries and uses the longest usable suffix. Conflicting successors remain alternatives. The local ring retains at most 65,536 tokens; persistent storage is bounded at 262,144 tokens; corpus loading is bounded at 16,777,216 tokens. Candidate storage and query depth are bounded. Tiered MTP, DFlash and PLD copy only bounded query suffixes; legacy standalone PLD retains its full-history search buffer.

Source confidence is calibrated from reached verifier outcomes, separately by exact matched suffix order (up to 64), lookup entry/continuation and raw-confidence bucket. A successful long template must not inflate the estimated reliability of a one-token suffix match. Chain selection uses each offered edge's actual conditional evidence, not repeated root confidence. Scheduling-clipped and rejected descendants are censored. Owned in-flight evidence preserves the selected order/confidence even when the next query replaces scratch. Duplicate neural/lookup proposals are correlated evidence, not independent probabilities to add together. Sibling projection preserves conditional descendant reach; pruning does not redistribute excluded mass.

Neural edges retain the host drafter's bounded raw conditional probabilities; only lookup entry/continuation probabilities learn online calibration. The earlier bucket-residual neural estimator did not demonstrate a coding throughput improvement and was removed. Mixed-source mass projection can still change ranking, so native-width selection now retains recorded native admission geometry whenever every selected edge already has neural support. Corroborating lookup evidence alone cannot displace that incumbent. New lookup paths and other widths remain eligible for competition; immutable offered lookup evidence remains available for reached-path learning.

The actual native action also remains eligible when a genuinely new lookup path enters at native width. Compare native and mixed actions using their separate projected rewards and actual kernel prices; native wins an exact economic tie. A known native variant cannot be displaced by an unknown mixed variant through ordinary adaptive selection. Cold bootstrap executes the actual native action, not a same-width mixed substitute. Forced widths retain their requested row count and diagnostic price prediction. This removes a dominated-action possibility; it does not introduce a near-tie margin or guarantee better realized acceptance.

Adaptive tiered DFlash also preserves the host's **backed-copy action** as a separate pre-assistant incumbent: the same 65,536-token scan window, at least 24 backing tokens, full native draft length and copy-silence eligibility. Its tokens are not reconstructed from the calibrated lookup winner or inserted with artificial confidence into lookup learning. Unknown copy economics retain the actual baseline action with null predictions. Once measured, copy competes using its own paired remaining duration/yield against lookup/plain and assistant alternatives; exact ties retain copy, and known alternatives share the existing periodic assistant recovery.

Only actual uncensored, nonterminal, solo copy executions supply copy cost/yield. Copy and assistant remaining clocks share the post-query, pre-policy boundary; neither timing population receives the other's samples. Per-width copy cells exclude the first valid execution and retain seven pairs. Existing context-map values grow by **960 bytes each** (hash-map spare capacity is additional allocated overhead), with no disk schema or second map. Query scratch adds **256 KiB of bounded stack space**; it is not retained per request. Full receipts retain the immutable lookup offer, separate native-copy identity and executed geometry hash. Unknown copy yield remains null, and copy selections are not counted as StairCut width reductions. Forced/cut/max, neural-only candidate controls and same-state diagnostics do not acquire this new routing action.

In greedy row-exact MTP and DFlash, the already verified, anchor-excluded target path also calibrates the retained full bounded lookup offer. This uses accepted selected tokens plus at most one reached correction/bonus decision; rows beyond native rejection are not actual-prefix observations. MTP additionally learns reached selected-chain edges missing from the bounded offer, without double-counting overlapping edges. Feedback traverses matching pure-neural ancestors but learns only lookup-bearing edges, with no extra target evaluation/readback. Verified outcomes beyond publication EOS may train conditional probabilities, but are not realized generation yield; EOS-censored native cost/yield samples remain excluded. Other modes retain selected lookup-candidate learning.

Tiered lookup proposals on these two greedy row-exact paths require **request-local evidence** before admission; the separately preserved native backed-copy action follows its existing eligibility and its own measured economics. Request support separates entry/continuation and confidence bins but pools suffix orders, allowing a verified copy to continue as its matched suffix grows. Model-pooled calibration still distinguishes exact suffix orders. No reached hit means zero local support; otherwise the Beta(1,1) predictive mean caps the order-specific model estimate. This is an admission heuristic, not a confidence bound: long-match hits can support unrelated shorter matches, and pooled support does not eliminate costly misses. The full bounded offer remains available for learning when its execution copy is restricted. Conditional evidence is independent of parent reach, so a supported continuation can follow an accepted neural parent without reviving an unsupported lookup entry. Request support resets between requests and participates in diagnostic state identity. The exact-order request-table experiment was removed after matched MTP evidence showed lost productive growing-copy reuse; this removes its additional 8 KiB/request. DFlash showed an edit-repeat tradeoff, so the simplification is not a universal performance claim.

Selection maximizes expected committed tokens divided by already-paid preparation plus verification/commit cost **among admitted width actions, after native-incumbent retention**. Other actions are stable marginal-reach ranked prefixes, with ancestors before descendants. Every admitted width is evaluated rather than stopping at the first locally unprofitable addition. This is not exhaustive optimization over every possible ancestor-closed tree: different shapes can use different kernels. The actual selected geometry—not the full offered tree—determines generic versus linear-GDN pricing; the latter requires a proven chain above eight rows on the supported tree verifier. Ordinary MTP/PLD chain prices remain generic. Unknown prices are estimates, not measurements: cold DFlash selection retains the caller's executable native width, and unknown native MTP economics retain the native incumbent.

This is **not** a universal router between loaded MTP, DFlash, DSpark or other model families. It selects history/neural proposals and verification work within the configured supported mode. Another drafter needs a compatible proposal/confidence adapter and exact verify/commit semantics. An opaque plugin needs an interface change.

Tiered DFlash constructs up to fifteen neural candidate nodes before selecting verifier rows; native DFlash retains its architecture-specific proposal limit. This does not increase the production assistant's configured draft-position horizon: a horizon-seven offer can commit at most eight tokens, even with fifteen candidate nodes. Native-width incumbent retention prevents pure-neural reranking; genuinely new lookup paths and wider alternatives can still change geometry, so native versus tiered fixed-eight is not a pure width ablation. Same-state `production-neural` diagnostics preserve that horizon; `merged16` deliberately prepares sixteen assistant positions. Neither verifier-only calibration establishes complete-round performance.

## Timing and learned routing

- Verification prices measure settled target verification **and committed state**, not lazy graph construction. Context labels are `0` below 2,048, then lower power-of-two bounds `2048`, `4096`, `8192`, etc., capped at `262144`.
- Priors, settled observations, extrapolation and warmup are keyed by execution kind, context, actual row count and actual generic/linear-GDN kernel variant. The first valid execution of a shape is excluded; invalid observations do not consume warmup. Exclusion from learning does not erase user-visible cold latency. Prices for another variant cannot justify bypassing an assistant.
- Adaptive tree-width competition requires a measured price for the exact width/context/kernel variant. Synthetic extrapolation cannot win merely because preparation is expensive. Requested fixed/max actions retain diagnostic prediction and actual execution timing; bounded native bootstrap and explicit learning remain separate from the priced competition.
- Both families can reserve one upper-width shape per kind/context, with at most one retry after a real cold execution; a naturally cold shape has only its remaining retry. MTP requires fresh measured native economics, an actually priced narrower chain reference, and greater current calibrated yield than that reference. Its wider-yield screen divides by paid query, the wider action's known preparation cost when applicable, and the narrow reference's verification time; native divides by query plus native remaining duration. Missing preparation retains an explicit zero-additional-preparation hypothesis, not a fabricated observation. The zero-added-verification-latency hypothesis is neither a wider-width price nor a mathematical latency bound. Losing hypotheses leave reservations unspent; current economics are checked again on a cold retry. Missing preparation alone never opens or renews this verifier-based budget. DFlash prices actual selected geometry and retains the actual native action as a separate eligible competitor. These bounded learning actions do not prove widening is faster. Reservations are consumed before execution, including cancellation or invalid timing. Fixed/max controls, routed assistant-free rounds and same-state diagnostics do not consume them.
- Standalone PLD can reserve one wider chain shape and one actual-cold retry per context after measuring its root-chain reference. Only a capped linear offer with positive calibrated gain qualifies. Empty, shorter or zero-gain offers do not spend the reservation; a later longer offer does not reset it. This breaks root-only price starvation without unlimited probing or synthetic cost observations. Explicit fixed/maximum controls, co-tenancy and counterfactual diagnostics do not use these reservations.
- Native fallback samples preserve a **pair: remaining round milliseconds and expected committed tokens**. Compare `(current query cost + remaining round cost) / expected tokens`. Adding query milliseconds to an already normalized milliseconds/token value is dimensionally wrong.
- Adaptive DFlash queries once before assistant admission. Its remaining-work clock begins after that query and ends after settled commit. Lookup-only and assistant-first forced rounds cannot overwrite this native cost history. Bypassing the assistant uses the exact priced alternative, not a second speculative reselection.
- Adaptive MTP obtains at most two clean calibration opportunities per missing context/request: first valid sample excluded, second learned. Only these opportunities suppress overlapping successor preparation. The timer ends before successor predrafting. Native baseline requests, forced lookup controls and already-priced contexts retain their normal pipeline. Budget/EOS-censored yields are ineligible. Calibration gaps remain part of cold end-to-end latency.
- For the proven Qwen MTP head only, those same two opportunities also settle the existing draft/head graphs and KV cache before starting a separate target verification/commit timer. This is an explicit synchronization cost, not an extra model forward. The independent native remaining-duration timer includes it. Target prices retain normal per-shape cold exclusion; different widths or invalid observations may leave bootstrap incomplete rather than inventing a price or adding unlimited probes. Prepared/grouped/lookup flights and Qwen4 heads are excluded. Receipts expose head-settlement time, target duration and price eligibility/learning.
- Native MTP's exact-depth controller retains verified acceptance from timing-excluded recovery and clean diagnostic probes, while excluding those durations from ordinary pipeline costs. Request-local prices require consecutive equal-width, equal-shape cycles: either carried preparation plus a fully built same-width native successor, or entirely cold rounds. Changed outgoing widths, discarded lazy work and pipeline entry/exit cannot seed local overrides. Shared legacy estimates remain fallback evidence, including their existing transition limitations. Context changes clear local costs and the old interval. The existing 64-plan alternate-depth challenge remains; the unproven additional request refresh was removed. A short request can still inherit a stale alternative price. This applies to native and lookup-enabled MTP.
- The row-exact MTP lookup comparator retains paired current-request native duration/yield at the selected depth, subtracting query preparation measured over the same cycle interval. At admission it copies the eligible duration and uses a separate request/context/depth yield EMA over all uncensored native completions. Recovery and contention may supply yield, never latency; lookup, errors, terminal/budget truncation and old-context completions do not. Yield cannot create missing timing. `request_cost_current_yield` names this factorized prediction; the original paired record is unchanged. Its populations can differ in age and selection, so it is not a newly measured contemporary native rate. Width trials use the same prediction, without additional GPU probes or depth pinning.
- Model policies and immutable read-only indexes survive requests; file locks do not. `[lookup-setup]` separates local/corpus/persistent setup and cache hits. `[lookup-native-cost]` reports eligible samples and pipeline gaps. `[lookup-round]` receipts distinguish selected/accepted work and decision inputs.
- `[lookup-native-depth]` logs the native controller's host-side acceptance and depth-price inputs when receipts are enabled. It describes a planning call before caller depth bounds, not necessarily an executed round: a successor may be prepared or lookup may override the plan. Logging performs no GPU evaluation/readback, but its CPU/I/O cost can affect wall-clock prices. Treat traced binaries as diagnostic evidence, not instrumentation-free throughput.
- `[lookup-native-yield]` records eligible completed native outcomes, executed depth, sample count and updated predicted yield. It is not timing evidence and is distinct from native-depth planning calls.
- Row-exact MTP lookup admission corrects a previously omitted cost: each width's known post-query lookup preparation is added only to that lookup alternative, before width selection. Native retains query plus its query-adjusted cycle cost. The bounded model-owned estimator separates nine context buckets, cold/carried scope and widths 1–15, excludes each cell's first actual valid execution and retains seven samples. It adds **9,720 bytes per policy**, no disk profile fields, trial storage or estimator heap allocation. Unknown preparation remains an explicit routing hypothesis; verifier prices and acquisition budgets are unchanged. Isolated-probe fallback, DFlash and standalone PLD do not use this surcharge.
- Full `[lookup-mtp-preparation]` receipts expose eligibility, learned state and nullable known cost. Cold preparation closes at the same timestamp that starts verification; carried preparation freezes at handoff and adds only disjoint resumed preverify time, excluding the scheduler gap. Shadow requery, missing/reversed boundaries, scope mismatch, grouping, width clipping and detected co-tenancy reject learning. Acquisition is independent of receipt mode for the scoped row-exact path; publication-only/off omit the records, not the measurement. The optional flight snapshot occupies **112 bytes**, 16 more than the preceding diagnostic version. The interval includes policy work, common history materialization and existing settlement—not pure stash time or an incremental switching penalty.
- **Remaining MTP cost limitation:** known preparation corrects omitted lookup work, but native inter-round cycles and lookup active preparation/verification still have different scheduling scopes. Unknown lookup preparation is not measured zero; cold native probes cannot price a carried alternative. The estimator neither identifies exact common-history attribution nor establishes same-state total-action routing. Scheduler eligibility also cannot detect another process using the GPU.
- Route receipts retain `lookup_rows`, `lookup_expected_tokens`, `lookup_variant` and `lookup_verify_ms` for the best priced lookup alternative. They describe the pre-assistant comparison, not necessarily the executed tree. Check `alternative_source` and `decision.skip`; the verifier cost is a historical exact-key estimate, not a new timing sample.
- With `MLX_SERVE_LOOKUP_PRICE_TRACE=1`, `[lookup-route-price]` also retains losing and unpriced ranked-prefix alternatives: actual width/variant, expected yield, exact-key verifier cost and query-inclusive milliseconds per predicted token. Unpriced costs remain null and cannot win admission. This is not a search over every possible tree; trace I/O perturbs round timing.
- With both price tracing and receipts enabled, `[lookup-native-candidate]` serializes native best-first admissions from the same expanded lattice, actual selected geometry and ancestry-aware membership. Native admission order is also retained for production incumbent selection; the diagnostic does not rebuild the lattice or alter the selection decision. These are offered token IDs, not published acceptance; join to exact row-exact greedy serial output and censor terminal continuation. Diagnostic work perturbs timing and the raw token IDs are private data.
- Carried MTP chains may be shortened by group admission. Learning uses the actual verified width, while receipts reconcile executed rows, expected yield, width price and source counts. Original offer hashes/counts and requested widths remain unchanged; a clipped forced action cannot claim that its requested width executed.
- Scheduler-known co-tenancy excludes wall-clock price learning while acceptance remains useful. It cannot detect another process using the GPU. Contended timings are descriptive, not causal speed claims.

Optional price files require `schema: 3` and `context_bucket: "floor-power-of-two-2048"`. Numeric context keys contain `plain`, `chain` or `tree`, then `generic` or `linear_gdn`, then width-to-millisecond tables. Schema two pooled variants and is rejected, not relabeled. Priors must match the actual model, device, numerical mode and measurement scope; file acceptance alone is not calibration proof. The component benchmark freezes price-file content and provenance independently of its held-out workload.

## Independent mechanism controls

- `MLX_SERVE_LOOKUP_CANDIDATES=0` retains supported DFlash neural tree construction and width selection while skipping suffix indexing, querying and external stores. `lookup_candidates` and `variant` in round receipts identify candidate controls and executed geometry. With MTP this control retains native MTP; it does not add neural-only MTP StairCut.
- Tiered standalone PLD uses capped **1/2/4/8 emitted plain-token miss backoff**, reset after accepted lookup. On an absent offer, unconstrained backoff-enabled selection enters the existing native pipeline immediately; that miss emission is outside the skip budget. Subsequent native and terminal-drain emissions count inside it. A clean one-token boundary still uses the synchronous cold path when no pending successor exists. No-match and zero acceptance advance the streak; an economic decline does not. Fixed/maximum controls retain their existing path. `MLX_SERVE_LOOKUP_BACKOFF=0` provides the matched ablation. Hybrid MTP/DFlash do not inherit standalone plain-step backoff.
- `[lookup-backoff]` records actual native/drain/cold token counts, remaining budget, misses and resets. Skipped cold steps refresh the context bucket before price learning and do not reuse the preceding lookup receipt. Legacy PLD retains its existing gates.
- Native miss-entry receipts retain the configured policy label but use `timing_scope: "native_entry_unsettled"`, null verification timing and `priced: false`. They account for publication without synchronizing the pending successor. The economics reducer rejects them as non-comparable rather than treating an asynchronous interval as a settled price.
- The same-state diagnostic accepts widths 1–16 and a predeclared training or evaluation case. Explicit `merged16` preparation retains a 16-position assistant with suffix merging; `production-neural` preserves the actual production horizon and disables suffix candidates; `production-combined` preserves that horizon with suffix candidates enabled. The latter permits both assistant and lookup actions, but does not imply a linear selected tree. Separate preparation groups cannot share an oracle/export. Actual ancestry, committed path and compaction accompany the existing first-offer, state, learner, dispatch, warmup and publication checks. Request-local trust still starts cold. These are readback-perturbed verification/commit timings, including host work—not learned-state admission, pure GPU or full-round throughput.
- `zig build ple-bench -Doptimize=ReleaseFast -- ...` measures real learned-table hash/gather implementations without loading the full target. The bounded 1,024-row four-way decoded cache accelerates eligible narrow gathers, retaining pooled misses and wide dispatch; it adds 663,840 logical bytes at dimension 160, no disk files or workers. Baseline-production, cached-production and forced serial/pool controls must produce identical vectors. Sequential 32/128-token cohorts retain cache state across repeats and changed suffixes; `--text` accepts a frozen coding corpus. First-access OS cache is uncontrolled, and component wins are not end-to-end model gains.


## Persistence and privacy

Only published prompt/output documents are persisted, never rejected drafts. The host `MLXLOOK1` format contains a tokenizer SHA-256 and little-endian token IDs separated by `1 << 30`. Missing/wrong-tokenizer/malformed stores are refused. Corpus input is the public NumPy format (`tokens.npy`, `sa.npy`) plus validated metadata; no external source builder is required.

Stable advisory locking protects append/trim. Trimming atomically replaces complete documents and syncs the directory. Partial append rolls back; failed rollback retires the store. Unsafe symlinks/hard links are rejected before permission changes. A reserved interrupted replacement is recovered under the stable lock. Read-only leases validate file identity and never chmod or rewrite the frozen fixture. Cooperative locking is required; metadata checks do not defend against an arbitrary malicious writer that ignores the protocol.

POSIX writers enforce directory mode `0700` and file mode `0600`. Windows follows the host's inherited-ACL convention and does not tighten or validate ACLs: place the configurable store beneath a directory with an appropriately restrictive **inheritable ACL**. New replacement files inherit the directory ACL, not necessarily an old payload's explicit ACL. Windows compilation is not evidence of private ACLs or runtime locking/durability correctness.

Token IDs are reversible data, **not anonymized text**. Enabling persistent storage retains prompts and answers across requests. Use private directories separated by tokenizer and trust boundary. Raw diagnostic logs can contain text, token IDs and temporary authentication credentials; do not publish them without redaction.

## Model and numerical boundaries

| Feature | Local Qwen3.8-27B pack | Qwen3.8-Flash-Next |
|---|---|---|
| Local/corpus/persistent lookup | Supported host chain/tree mechanisms | Host chain mechanism; runtime not established by 27B results |
| Native MTP | In-checkpoint head available | Host `qwen4_exp` path exists; not exercised by this feature's 27B checks |
| DFlash2 tree integration | Compatible `incoai/Qwen3.8-27B-DFlash2`; dense row-exact Qwen verifier | `qwen4_exp` excluded by tree support; do not bypass architecture checks |
| Memory | Target plus assistant previously fit the 64-GiB machine at small context; admission still enforced | Standalone v25 CLI completed exact 59-token cache-off/on requests at 45.914 GiB printed peak. Server preflight needs about 55 GiB, above this device's measured 51.84-GiB Metal recommendation; closing apps alone cannot remove that ceiling. `MLX_SERVE_ROW_EXACT=1` is an explicit numerical reference, not a promise of stock MTP output bytes. Unsupported/uncovered execution fails closed, and the prompt-cache namespace is isolated. Compare every arm in the same numerical mode. Ordinary non-row-exact chain reductions can differ from serial; this feature does not repair the preexisting PLD raw-argmax versus reserved-token suppression difference.

Remaining output tokens bound tree **depth**, not competing sibling count. The native pre-scaled 4-bit projection covers up to 16 rows. The retained host-native GDN linear specialization is used only above eight rows and only for proven chains: earlier microbenchmarks found a width-eight regression. Native acceptance/KV/SSM commit algorithms remain authoritative.

## Exercise and validate

```sh
M="$HOME/.mlx-serve/models/ddalcu/Qwen3.8-27B-MLX-Serve-4bit"
D="$HOME/.mlx-serve/drafters/incoai/Qwen3.8-27B-DFlash2"
MLX_SERVE_LOOKUP=1 MLX_SERVE_ROW_EXACT=1 \
  ./zig-out/bin/mlx-serve serve --model "$M" --drafter "$D" \
  --host 127.0.0.1 --port 18097 --ctx-size 2048 --no-vision
```

Set `MLX_SERVE_LOOKUP_CORPUS` and/or `MLX_SERVE_LOOKUP_STORE` to opt into external tiers. `MLX_SERVE_LOOKUP_STORE_WRITE=0` freezes persistent history. Omit `--drafter` for the target's native MTP configuration. `MLX_SERVE_LOOKUP=0` retains existing native behavior. Never bypass memory admission.

Correctness checks cover publication identity, tree compaction and continued KV/SSM state, clipping/censoring, store boundaries, and actual execution. Performance checks must compare **both native MTP and native DFlash**, separately report cold first exposure and timed repeats, and include conflicting-history and unrelated misses. Exact replay demonstrates a cache-hit mechanism; frozen-history unseen related requests demonstrate transfer. Neither alone proves standard-benchmark improvement.

Same-state diagnostic windows restore the full learner before two identical requests, including request-local trust, fingerprint actual target/assistant state and dispatch geometry, and match complete published tokens to a current-binary serial oracle. The validator requires the request-trust identity field; old receipts cannot be upgraded into current evidence. These windows report verify/commit time only; full-round duration is deliberately unavailable. GPU readback perturbs execution, so they are not throughput benchmarks. Strict-authenticated single-slot diagnostics admit exactly two requests and reject a third with the explicit request-limit error.

Diagnostic offer hashes cover the full merged selection offer. Lookup rows excluded by its merge cap can still be off-policy learning inputs; that hash alone does not enumerate those rows. Common-state fingerprints cover the deterministic frozen history, prefix and learner inputs. Verification-only width comparisons must not be presented as a measurement of all unselected alternatives.

Performance qualification requires declared GPU isolation plus complete stable power/thermal/memory-pressure/swap observations. Two balanced pairs are diagnostic; the adjacent-quartet confirmation protocol requires at least four complete qualified ABBA/BAAB quartets. Family-improvement and fastest-native gates are separate. Historical summaries cannot be promoted by relabeling their schema or schedule. A full canonical protocol that times out is incomplete, never a passing shortened benchmark.

See [results and evidence boundaries](lookup-staircut-results.md) and [offline operation](lookup-staircut-offline.md). Measurements are tied to exact binary identities; earlier revisions do not certify later changes.

## Proposed upstream review boundaries

The experimental branch is **not a minimal production PR**. At the v21/v22 working-tree review, the tracked diff against local `upstream/main` (`191da71d`) spans 49 files, excluding the unrelated user-owned `lib/mlxc-src` change. `src/generate.zig` alone contains 3,071 added and 100 removed lines, including inline tests and diagnostics—not 3,071 lines of new hot-path logic. Benchmark tooling and historical evidence account for substantial additional scope. These are review-surface counts, not runtime overhead.

| Review unit | Production boundary | Evidence and dependency |
|---|---|---|
| Learned-embedding decoded-row cache | `qwen4_exp` gather/cache path; existing PLE loader integration | Independently useful; exact-vector and sequential-request gather results. Approximately 648 KiB at the tested embedding dimension. No full-model speed claim. |
| Native numerical/verification prerequisites | Row-exact projection coverage, guarded GDN dispatch and host commit correctness | Review independently of lookup scheduling. Required capabilities must land before integrations that depend on them; kernel changes are not attributed to StairCut. |
| Opt-in lookup and width policy | Bounded history, request trust, admission/width economics, MTP/DFlash/PLD integration | Currently coupled through the policy and adapter. Treat as one dependent review unit unless the API is deliberately separated; do not pretend that extracting files produces independent features. Preserve disabled native behavior and storage/privacy controls. |
| Reproducibility and diagnostics | ABBA/BAAB runners, serial replay, runtime/model identity, telemetry, resource accounting and same-state witnesses | Tooling can be reviewed separately, but the production PR must link the exact frozen evidence used for each claim. Diagnostic-only hooks should remain opt-in and distinguish their timing overhead. |

Submission gates remain exact output/state correctness, adversarial review, explicit incremental cost, and appropriately scoped performance evidence. Related-template wins do not justify a universal coding or canonical claim. Do not include unsuccessful experiments merely because they were benchmarked: retain their evidence in the results document and remove unsupported complexity from the final production series. All units retain concept attribution and the independently authored, upstream-based history; no TandemLLM implementation or unrelated submodule change belongs in the series.
